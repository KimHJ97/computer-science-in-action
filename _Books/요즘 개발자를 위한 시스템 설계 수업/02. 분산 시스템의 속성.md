# 분산 시스템의 속성

## 1. 호텔 객실 예약 시스템으로 살펴보는 분산 시스템 예시

예약 서비스는 복제 데이터베이스(db1, db2, db3) 세 개와 연동하고 있다고 가정한다. 이떄 쓰기 작업의 결과를 다른 레플리카 데이터베이스에 적용하는 방법은 2가지가 있다. 하나는 앱 서버가 모든 래플리카에 직접 쓰기를 수행하는 방식이고, 다른 하나는 데이터베이스 자체에 복제 기능이 있어 앱 서버가 직접 하나씩 쓰기 요청을 하지 않아도 쓰기 작업이 자동으로 모든 레플리카에 적용되는 방식이다.

 - __쓰기 요청 흐름__
    - 사용자가 방을 예약한다.
    - 사용자(클라이언트)는 API를 이용하여 앱 서버에 예약 요청을 보낸다.
    - 서버는 하나 내지 여러 레플리카에 데이터를 기록한다.
 - __데이터 쓰기 옵션__
    - 직렬 동기 쓰기
        - 서버가 DB1에 데이터를 쓰고 처리 완료 응답을 받은 후 DB2에 쓰고 응답을 받으며, 마지막으로 DB3에 쓰고 응답을 받는다.
        - 이후 최종적으로 클라이언트에 확인 응답(예약 완료)를 보낸다.
        - 이 경우 사용자가 객실 예약을 완료하기까지 기다려야 하는 지연 시간은 매우 길어진다.
    - 직렬 비동기 쓰기
        - 서버가 DB1에 데이터를 쓰고 확인 응답을 받은 후 즉시 클라이언트에 응답을 보낸다.
        - 이후 다른 레플리카 2개는 비동기적으로 업데이트된다.
    - 병렬 비동기 쓰기
        - 서버가 데이터베이스를 모두 동시에 업데이트하지만, 모든 처리 완료 응답을 기다리지 않고 일부 응답을 받은 후 클라이언트에 확인 응답을 보낸다.
        - 지연 시간은 낮지만 스레드의 자원 사용량이 높다.
    - 메시징 서비스에 쓰기
        - 카프카 등 메시징 서비스에 데이터를 기록한 후 클라이언트에 바로 응답을 보낸다.
        - 이후 메시징 서비스에 저장된 데이터를 읽어 오는 시스템이 이 데이터를 가져가서 앞서 설명한 방법 중 하나로 각 레플리카에 데이터를 적용한다.
        - 지연 시간이 가장 짧고, 쓰기 요청이 아주 많아도 문제없이 처리할 수 있다.
 - __데이터 읽기 옵션__
    - 하나의 레플리카에서만 읽기
        - 하나의 레플리카 데이터베이스에서만 데이터를 읽어와 클라이언트에 반환한다.
        - 경우에 따라 오래된 데이터가 반환될 수 있어 데이터의 정확성 문제가 발생할 수 있다.
    - 일부 레플리카에서 읽기
        - 과반수에 해당하는 데이터를 읽어와 일관성을 확인한 후 클라이언트에 반환한다.
    - 모든 레플리카에서 읽기
        - 모든 레플리카에서 데이터를 읽은 후 그 결과를 클라이언트에 반환한다.
        - 정확성 문제는 해결할 수 있지만, 속도가 느려질 수 있다.

## 2. 일관성

일관성은 모든 노드가 동일한 데이터를 저장하고, 같은 업데이트 요청에 대해 동일한 순서로 업데이트된 데이터를 반환하도록 하는 것이다.

<br/>

### 2-1. 강한 일관성

강한 일관성이란 시스템 내 모든 노드가 공유하고 있는 데이터 업데이트를 동일한 순서로 처리하도록 보장하는 특성을 의미한다. 강한 일관성은 쓰기 작업이 수행된 이후의 모든 읽기 작업이 항상 최신 값을 반환하도록 한다.

 - 모든 노드가 동일한 순서에 따라 데이터를 업데이트하도록 보장
 - 시스템이 예측 가능하고 직관적인 방식으로 동작
 - 시스템 상태에 대해 확신을 갖고 작업을 수행하는 순서에 따라 시스템이 어떻게 반응할지 쉽게 추측하는 것이 가능
 - 각 노드가 데이터의 업데이트 순서에 동의할 때까지 기다려야 하기에 처리 속도가 느리거나 시스템 가용성이 떨어질 수 있음
 - 예시: 은행 및 금융 시스템에서는 계좌 잔액이나 거래 내역 같은 민감한 데이터를 다루기 떄문에 강한 일관성을 보장하는 것이 매우 중요

<br/>

### 2-2. 최종 일관성

최종 일관성은 시스템 내에서 일시적이나마 데이터 불일치를 허용하지만, 시간이 지나면 모든 레플리카 데이터베이스나 노드가 결국 동일한 상태에 도달하도록 보장하는 방식이다. 즉, 시스템에 각 노드를 비동기적으로 업데이트하지만 최종적으로는 모든 레플리카가 동일한 값을 가지게 된다.

최종 일관성 문제는 충돌 해결, 데이터 복제, 가십 프로토콜 같은 기법을 사용해서 해결할 수 있다. 예를 들어, 서로 다른 노드에서 동일한 데이터에 대해 동시에 업데이트하는 경우와 같은 충돌이 발생하면, 시스템은 충돌 해결 전략을 적용하여 차이를 조정하고 데이터를 일관된 상태에 도달하도록 한다. 데이터 복제 전략은 데이터를 여러 노드에 복사하여 유지하는 방식으로, 하나의 노드에서 업데이트되면 그 변경 사항이 다른 레플리카에도 비동기적으로 전달되로고 한다. 이것으로 시간이 지나면 모든 레플리카가 동일한 데이터를 가진다. 가십 ㅍ ㅡ로토콜은 시스템 전체에 업데이트가 서서히 전파될 수 있도록 한다.

 - __장점__
    - 가용성과 확장성을 높이고, 클라이언트에 더 빠른 응답 시간을 줄 수 있다.
    - 네트워크 분할이나 일시적인 장애가 발생해도 각 노드가 계속해서 운용되며 요청을 처리할 수 있다.
    - 작업 부하를 여러 레플리카에 분산할 수 있다.
 - __단점__
    - 애플리케이션은 분산 시스템에서 각 노드가 동일한 데이터에 대해 서로 다른 버전이나 값을 가질 수 있는 상황을 처리할 수 있어야 한다.
    - 충돌 해결, 버전 관리, 조정 알고리즘 등 기법을 이용하여 최종적으로 모든 노드가 일관된 상태에 도달해야 한다.

<br/>

## 3. 가용성

가용성이란 시스템에 장애나 오류가 발생하더라도 사용자에게 서비스를 지속적으로 제공할 수 있는 능력을 의미한다.
